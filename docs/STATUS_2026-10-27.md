# DeepNode overhaul - status (2026-10-27, session 2)

Goals given: (1) 70-80 fps with 8 Percherons, (2) rut updates >= 40 Hz so ruts keep up with the
wheels at ~45 km/h, (3) memory growth < 20 MB/min, (4) fix decal roads over the mud.
User priority (said during the session): decal roads and rut speed first, then fps.

Benchmark: gridmap_v2, 8 Percheron s450_8x8_flatbed_A, straight through the mud + sand pits,
user-folder `lua/ge/extensions/dntestRun.lua` (spawn file `/settings/deepnode/bench_spawn.json`,
headings must be d = {0,-1}), scripts in `~/.claude/skills/beamng-deepnode-dev/scripts/`
(`bench2.py label runs [clear]`, `reload.sh`, `profrun.py`). Physics mode is `heavy` (user
gui.json): the trucks bog down to ~3-4 m/s in the mud, so 45 km/h is not reached there.

## What changed

1. **Decal roads (fixed for heavy physics):** "terrain-first" drawing. `physics.heavy.floorLift.mud = 1`
   (full lift) leaves the terrain under undisturbed mud untouched, so the terrain itself draws the
   mud with the level's own DecalRoads (identical to vanilla), grass and colours, to any distance.
   The mod draws only dug squares/cells (`P.squareFlush`, `P.tileFlush`, emitters in tileMesh,
   sectors in farMesh), lifted 6 mm (tiles) / 3 mm (sectors) over the terrain. The rut floor
   (physics.lua) now lowers terrain only under carved cells and reports changes
   (`main.onFloorChanged`). Mud `defaultDepth` 0.2 -> 0.25 keeps the same maximum sink.
   Grass lift uses the visual depth (sink - lift). Mud mesh geometry at start: 809K -> 47K corners.
2. **Rut speed:** predictive stamping (wheel sweep ends at position + velocity x lead, lead adapts
   to the measured front latency, 15-60 ms); fresh rut fronts (untouched mud carved now) in the
   camera view and within 40 m rebuild at up to 40 Hz outside the frame-rate governor, uploads
   coalesced every 2nd frame (`ring.digEvery`, `perf.uploadEvery`); smallChangeWait 0.4 -> 0.1 s,
   bodyMaxWait 0.6 -> 0.1 s; vehicle reports 15 -> 20 Hz, chassis nodes every 2nd report.
   New readout: `deepnode_main.rutLag().fresh` (front latency).
3. **Performance/memory:** tyre mud material flushes and per-frame transforms only for trucks in
   the camera view, 1 flush per frame; decal UV cache found to be bounded (Lua heap flat).

## Engine limits found (measured, see memory notes)

- Every frame that first draws a freshly uploaded ProceduralMesh costs ~1 ms in the shadow pass
  (+0.2 ms reflections), whatever its size, even with castShadows off; several uploads in one
  frame partly add up. createMesh itself: ~0.35 ms + 0.18 us per face corner + 0.38 us per vertex.
- Nothing found that avoids it (render views, collision type, show delay, moving, other classes).
  This is why 40 Hz rebuilds of every dug tile for 8 trucks cannot reach 70+ fps; the fast path
  is limited to what the camera sees.
- Never create a TerrainBlock at runtime (crashed the game this session).

## Open / next steps

- fps: still ~5-6 ms over vanilla (engine cost per upload frame ~2-3 ms, Lua ~2.5 ms, tyre mud).
  Ideas: fewer uploads per visible dig (smaller dirty regions), cheaper report parsing
  (binary/compact strings), Lua GC pressure in stamping, frozen tile objects (200 own meshes).
- Deepening of ruts behind the front axle is budgeted (8 Hz target, can lag under load).
- Sand still uses the old fully meshed surface (floorLift.sand = 0); setting it to 1 would give
  sand the same decal/distance fix but changes sand physics (needs a deeper sand ground model).
- Vanilla physics mode still uses the overlay decals (terrain-first needs the heavy rut floor).

## Cost attribution at the end of the session (repeat runs, mod 19.2 ms vs vanilla 12.8 ms per frame)

- idle mod (no digging, reports no-op): ~1.8 ms (Lua ~0.8, mud objects in shadow/reflection passes)
- tyre mud: ~1.6 ms (mostly engine shadow pass; materials already castShadows 0)
- rut pipeline (reports, stamping, tile uploads and their engine cost): ~2.9 ms
- Vanilla physics mode checked: starts cleanly, terrain-first off (old overlay decals).
- Tuning knobs for the speed/fps trade-off: perf.uploadMsMin (budget floor for deepening
  uploads; higher = less deepening lag, lower fps), ring.digEvery (1 = fresh fronts every frame),
  ring.deepenRebuildHz, ring.digNearDist.
